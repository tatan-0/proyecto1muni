# SGR La Serena Etapa 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert the approved SGR prototype into a Django application with role-aware views, persistent CRUD for five master tables, unit tests, and aligned security, 4+1, and AWS deployment documentation.

**Architecture:** Keep a server-rendered Django monolith in the existing repository and add a `gestion` app. Use SQLite for local development and environment-configured MySQL for AWS RDS; keep operational activities and commitments as clearly labelled, read-only demonstration views during this course stage.

**Tech Stack:** Python, Django 5.2.17 (existing pinned dependency), SQLite, MySQL on Amazon RDS, AWS Elastic Beanstalk, Django templates/forms/tests, DaisyUI 5 with locally built static CSS.

**Spec:** `docs/superpowers/specs/2026-10-19-sgr-etapa-2-design.md`

## Global Constraints

- Use the local Django project as the implementation base; the ZIP project is reference material only.
- Implement persistent CRUD for Delegación, Cargo, Funcionario, Indicador/función, and Servicio.
- Restrict catalog writes to the Administrador profile; scope Delegado and Funcionario reads as described in the spec.
- Keep activities, evidence, and commitments read-only and clearly marked as demonstration data in this stage.
- Use fictitious records; do not add real RUTs, phone numbers, or other personal data.
- Validate all writes on the server and use Django CSRF protection.
- Keep secrets outside the repository; production uses `DEBUG=False`, explicit `ALLOWED_HOSTS`, secure cookies, and HTTPS.
- Use SQLite locally and environment-configured MySQL for production.
- Prepare AWS configuration and instructions; do not create billable AWS resources without a separate team decision.
- Keep diagrams and security documentation consistent with the final code and deployed configuration.

## Review Focus

- Missing or malformed production secrets/hosts must prevent an unsafe production startup. Test: `test_production_settings_reject_missing_secret_and_hosts` in Task 1.
- Anonymous requests to protected views must be redirected to login or denied. Test: `test_anonymous_user_cannot_open_dashboard` in Task 3.
- A logged-in user must not read another delegation's staff data by changing a URL. Test: `test_delegate_cannot_read_other_delegation_staff` in Task 3.
- Invalid or duplicate master data must produce field errors without persisting rows. Test: `test_indicator_rejects_invalid_weight_and_target` in Task 2 and CRUD invalid-form tests in Task 4.
- Deactivating a related master must preserve historical references and remove it from active selectors. Test: `test_deactivation_preserves_relations_and_hides_from_active_lists` in Task 4.
